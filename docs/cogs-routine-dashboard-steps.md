=== DASHBOARD SYNC (Potties Order Desk) ===
The fulfilment dashboard lives at https://potties-orders.netlify.app . Call its API with HTTP requests (Python `requests` or curl) and always send the header:
  Authorization: Bearer <INTEGRATION_TOKEN>
Rule of ownership: the COGS sheet is the master for money (invoices, amounts, payments); the dashboard is the master for fulfilment (stages, ship-by dates, couriers, tracking, proof photos, packing slips). Never change dashboard order stages from the sheet, and never overwrite paid amounts the sheet already has. The dashboard sync runs every day, even when the normal refresh finds nothing new.

D1. After step 1, GET https://potties-orders.netlify.app/api/integration/export?since=<UTC midnight 2 days ago, ISO 8601> and save it as dashboard.json. If this fails (network error, 401, 503), skip D2–D5, mention the exact error in the summary, and carry on with the normal refresh.

D2. Fulfilment into the sheet: before step 5 publishes, add or replace a tab named "15. Fulfilment" in live.xlsx (openpyxl; do not touch tabs 1–14 or their formulas). Title row "POTTIES — FULFILMENT STATUS (from the Order Desk, <date>)", then one row per order in dashboard.json "orders": Order | Customer | Town | Stage | Ship by | Sent to foundry | Accepted | Packed | Shipped | Delivered | Courier | Tracking | Custom text | Proof approved | Foundry invoice | Dashboard link. Dates as yyyy-mm-dd. If step 5 would be skipped because nothing else changed, still publish when the fulfilment data differs from the tab already in the live sheet.

D3. Invoices into the dashboard: after step 4, read every data row of tab "8. Invoices" in the refreshed live.xlsx (not only new ones) and POST them in one request to https://potties-orders.netlify.app/api/integration/invoices as JSON {"invoices":[...]} where each item has: supplier (e.g. "Foundry", "LL Manufacturing", "Huntlea"), number (invoice/PO number), amount (incl VAT, number), issuedAt and dueAt (yyyy-mm-dd; due = when the balance is due), paidAt (yyyy-mm-dd only when fully paid, else null), paidAmount (number or null), orderName (Shopify order like "#1004" if the row is for one order, else null), poNumber (or null), driveUrl (the webViewLink of the invoice PDF in Drive > Invoices or Purchase Orders, if you can find it by number, else null), notes (short, optional). Skip rows without a number or amount. Record the response counts (created, updated, skipped, unmatchedOrders) for the summary.

D4. Documents into Drive: in the Drive folder "Potties" create (if missing) a folder "Fulfilment", and inside it one folder per order named like "#1004". For every order in dashboard.json with a packingSlipUrl, download the packing slip PDF (with the Authorization header) and save it there as "packing-slip-<order>.pdf" unless a file with that name already exists. Do the same for every item in dashboard.json "files" (proof photos, waybills, artwork, invoices, proofs of payment), naming them "<kind>-<original filename>". Limit to 30 files per run; say in the summary if more are waiting. If the Drive connector cannot upload binary files, save them under G:\My Drive\Potties\Fulfilment\<order>\ on the computer instead.

D5. Gmail documents to orders: when searching the potties@pottiespots.co.za mailbox in step 3, also look for emails from the last 2 days with PDF or image attachments that are courier waybills, collection notes or lid/engraving artwork and that mention a Shopify order number. Save each attachment into the matching Drive > Potties > Fulfilment > <order> folder and POST {"documents":[{"orderName":"#1004","kind":"WAYBILL"|"ARTWORK"|"OTHER","driveUrl":"<webViewLink>","filename":"<name>"}]} to https://potties-orders.netlify.app/api/integration/documents.

D6. At the very end, POST {"source":"cogs-routine","ok":true|false,"summary":"<one line: invoices created/updated, fulfilment rows, files archived, problems>"} to https://potties-orders.netlify.app/api/integration/report (ok=false if any step failed). This line is shown on the dashboard.

In the step 6 summary to Stephan, add a "Dashboard" line: orders late or due in 3 days (from dashboard.json), foundry questions waiting, proof photos waiting for approval, invoices synced, files archived, and any order numbers or invoices that could not be matched.
